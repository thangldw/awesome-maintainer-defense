# Awesome Maintainer Defense v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Maintainer Defense Kit 1.1.0 with a working first run, current GitHub Actions authority analysis, adoption controls, reproducible dogfood evidence, verified distributions, and updated GitHub, PyPI, and ChatGPT plugin releases.

**Architecture:** Extend the existing dependency-free single-file Python implementation through focused pure functions and corpus-driven rules while preserving schema-v1 reports and patch-only fixes. Keep comparison/suppression metadata in stderr and a separate pilot evidence schema, restore least-privilege repository automation, and publish every distribution from one verified release commit.

**Tech Stack:** Python 3.10+ standard library, `unittest`, JSON Schema documents, Git/GitHub Actions, setuptools/PEP 517, PyPI Trusted Publishing, Codex skills-only plugin bundle.

**Spec:** `docs/superpowers/specs/2026-08-23-flagship-v1.1-design.md`

## Global Constraints

- Runtime requires Python 3.10+ and has zero third-party dependencies.
- Default audit is offline, read-only, token-free, and never executes target code.
- `fix` emits a patch and never edits the target repository.
- Existing audit JSON schema version 1 and existing rule fingerprints remain compatible.
- Pull-request CI has no write permission and every Action uses a reviewed 40-character SHA from `pins.json`.
- Release version is exactly `1.1.0`; Git tag and release path are exactly `v1.1.0`.
- No repository scoring, contributor attribution, automatic closing/locking, hosted dashboard, or live settings audit.
